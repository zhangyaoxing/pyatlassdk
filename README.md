# pyatlassdk

Python SDK for the MongoDB Atlas Administration API, generated automatically.

> Everything under `src/pyatlassdk/` is generated by [mongo-atlas-sdk](https://github.com/zhangyaoxing/mongo-atlas-sdk). Do not edit it by hand.

## Installation

```bash
pip install pyatlassdk
```

## Usage

```python
from pyatlassdk import AtlasClient
from pyatlassdk.models.cluster_description20240805 import ClusterDescription20240805

# Digest authentication with Atlas API keys
with AtlasClient(public_key="...", private_key="...") as client:
    cluster = client.clusters.create_group_cluster(
        group_id="...",
        body=ClusterDescription20240805(name="demo", cluster_type="REPLICASET"),
    )

# OAuth 2.0 client credentials with Atlas service account credentials
with AtlasClient(client_id="...", client_secret="...") as client:
    cluster = client.clusters.create_group_cluster(
        group_id="...",
        body=ClusterDescription20240805(name="demo", cluster_type="REPLICASET"),
    )
```

- Authentication: Atlas API keys over HTTP Digest, or Atlas service account credentials over OAuth 2.0 (`client_credentials`). Tokens are cached and refreshed automatically; the constructor rejects mixed or partial credentials.
- `base_url` defaults to `https://cloud.mongodb.com/api/atlas/v2`; generated method paths are relative to it.
- Atlas requires a versioned `Accept` header. Each method sends the newest version declared for its successful responses (for example `application/vnd.atlas.2024-10-23+json`), plus a matching `Content-Type` when it sends a body. `DEFAULT_ACCEPT` and `DEFAULT_CONTENT_TYPE` are fallbacks for endpoints without a versioned media type.
- Models: pydantic v2 with snake_case fields; serialization uses the original Atlas field names (aliases).
- Resources: 55 resource classes with one method per endpoint, named after `operationId`.

## Regenerating

Run these commands from the `mongo-atlas-sdk` repository:

```bash
uv run mongo-atlas crawl       # fetch the OpenAPI document
uv run mongo-atlas normalize   # normalize it
uv run mongo-atlas pygen       # render templates into pyatlassdk/src/pyatlassdk
```

Then commit in this repository and publish:

```bash
uv build
uv publish
```

## Releasing

1. Bump `version` in `pyproject.toml`.
2. Commit, tag, and push:

```bash
git tag v0.1.0
git push origin main --tags
```

3. Create a GitHub Release from the tag. Publishing it triggers
   `.github/workflows/release.yml`, which builds the sdist and wheel,
   validates the metadata, and publishes to PyPI.

The workflow uses PyPI trusted publishing (OIDC), so no API token is stored.
Configure a trusted publisher at
<https://pypi.org/manage/account/publishing/> with:

- owner: `zhangyaoxing`
- repository: `pyatlassdk`
- workflow: `release.yml`
- environment: `pypi`

The release tag must be `v` plus the version in `pyproject.toml`; the workflow
fails if they differ.
